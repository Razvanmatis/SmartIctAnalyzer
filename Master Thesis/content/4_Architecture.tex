	\section{Grpc Server for using the PCB Investigator API}
This project is responsible for using the \ac{PCB}-Investigator API which is being created using the .NET Framework and was created as a console application using the .NET Framework 4.72 as well. It further derives a service which was provided by a \ac{GRPC} auto code generation as a server. The proto file itself which was used for the code generation contains three functions:
\begin{itemize}
	\item GetConvertedObjects(Request) returns (Result) - Within this function all objects of a specific project could be determined using the location to the project
	\item GetConvertedObjectsByZip(RequestZip) returns (Result) - That method obtains all objects by using the received project as zip file in bytes
	\item ClientAvailable(Empty) returns (StatusResult) - This function is being used to detect whether the client has a valid connection to the server using the settings or not
\end{itemize}

To make sure that the server itself knows which data it has to open actually only the GetConvertedObjectsByZip method is being used where the project to be opened will be transferred as a byte array containing the a single zip file.

\begin{lstlisting}[language={[Sharp]C},caption={GetPinsGrpc},captionpos=b,label=lst:GetPinsGrpc]
	public IList<PinGrpc> GetPinsGrpc(IList<IPinComponent> allPins, IList<INetComponent> allNets)
	{
			List<PinGrpc> pins = new List<PinGrpc>();
			foreach (IPinComponent pin in allPins)
			{
					IList<int> nets = GetNetIdsGrpc(pin.Nets, allNets);
					PinGrpc pinGrpc = new PinGrpc()
					{
							Geometrics = GetGeometricsGrpc(pin.GeometricAttributes),
							PinType = GetPinTypeGrpc(pin.PinType),
							PinNumber = pin.PinNumber,
					};
					pinGrpc.Nets.AddRange(nets);

					pins.Add(pinGrpc);
			}

			return pins;
	}
\end{lstlisting}

As described in \ref{lst:GetPinsGrpc} there could be seen that for creation of the serialized objects there were a couple of helper methods used to ensure a structured way of working. Further it will be clear that working with a list containing just int objects for referencing the net objects was necessary.

		\subsection{Events}
For being able to interact project wide with different classes within different projects without having the need always to reference directly a object of class of interest there was used a general event handling by using the ProMik.Core.Services.EventService.PrismEventService which is based on the PRISM event service as a nuget referenced package. In general the event handling works on one side by subscribing to any event type and on the other by publishing that specific event. To specify an event which could use by this service it was necessary to inherit from the class EventPayload. The following events are being specified within the Gui project itself:
\begin{itemize}
	\item AddPcbObjectsEvent - this event occurs when the importing of objects from the \ac{PCB}-Investigator API has been finished
	\item ChangeExportMenuItemEnabledStateEvent - will be created to toggle the enabled states of menu items for exporting data into file
	\item CloseAllSettingsEvent - event which will be called if the settings page will be closed
	\item ComponentsImportFinishedEvent - that event will be generated if the import of \ac{JSON} related data was finished
	\item HandleDropEvent - an event which will be called if something was dropped my mouse into the tool
	\item ResetLayersSelectionEvent - is being created to trigger the reset of all layers which will be shown within the view section
	\item ResetViewEvent - if the whole view needs to be reset then this event is being called
	\item SelectBomFinishEvent - after a bill of material file was successfully selected then this event will be created
	\item SendLayersEvent - to send all created layers after the read out from \ac{PCB}-Investigator API to the view this event is needed
	\item SetBusyEvent - for being able to set the state of the is busy animation of the application this event could be used
	\item SetCoverageValuesEvent - in order to update all test coverage determined values of objects this event needs to be used
	\item ShowObjectsEvent - showing of different kind of objects which are located in specific layers could be performed by using that event
	\item UpdateBomDataEvent - updating all bill of materials related data of objects could be performed by using this event
\end{itemize}

 private static void OnPropChanged(DependencyObject d, DependencyPropertyChangedEventArgs e)
{
		if (!(d is FrameworkElement fe))
		{
				return;
		}

		if ((bool)e.NewValue)
		{
				fe.AllowDrop = true;
				fe.Drop += OnDrop;
				fe.PreviewDragOver += OnPreviewDragOver;
		}
		else
		{
				fe.AllowDrop = false;
				fe.Drop -= OnDrop;
				fe.PreviewDragOver -= OnPreviewDragOver;
		}

	\section{Test coverage determination of loaded project}
The \textbf{TestCoverage} project which was implemented using the .NET Standard 2.1 framework is responsible for determining all test related objects and different kind of test coverage results to be displayed within the application as plain text. It consists of the following sub folders and content:
\begin{itemize}
	\item Events - here are the test coverage related events are placed which could be used for triggering some actions
	\item Helper - that folder contains some helper classes which are necessary to work with the other interfaces of this project in a comfortable way
	\item Interfaces - this folder consists of all interfaces which are being used by other projects to perform test coverage related actions and could be easily extended by providing new implementations for them
	\item Implementations - within that folder are actually just boundary scan related implementations of the interfaces to be used
\end{itemize}

Actually there is just been provided the possibility of determining boundary scan related values according the following sequence:
\begin{enumerate}
	\item Define the settings for general identifying the ICs within the tool
	\item Define the test coverage related settings within the tool
	\begin{itemize}
		\item ground nets related identifier
		\item ground nets related blacklist
		\item power nets related identifier
		\item power nets related blacklist
	  \item jtag nets related identifier
		\item jtag nets related blacklist
	\end{itemize}
	\item Load a \ac{ODB}++ project into the tool
	\item Perform the function \textbf{Determine all boundary scan objects} by menu item
	\item Perform the test coverage determination for at least one of the following values by clicking the according menu item:
	\begin{itemize}
		\item Determine test coverage for JTAGs - the amount of all \ac{JTAG} devices / amount of total pins of all \ac{JTAG} devices
		\item Determine test coverage for all PullUps - the amount of totally connected power nets of all \ac{JTAG} devices / amount of total pins of all \ac{JTAG} devices
		\item Determine test coverage for all PullDowns - the amount of totally connected ground nets of all \ac{JTAG} devices / amount of total pins of all \ac{JTAG} devices
		\item Determine test coverage for all PullUps and PullDowns - (the amount of totally connected ground nets + power nets of all \ac{JTAG} devices) / amount of total pins of all \ac{JTAG} devices
		\item Determine test coverage for all other components - the amount of totally connected nets which are neither ground nor power nets of all \ac{JTAG} devices / amount of total pins of all \ac{JTAG} devices
		\item Determine complete test coverage of boundary scan - (the amount of totally connected nets which are neither ground nor power nets + connected ground + connected power nets of all \ac{JTAG} devices) / amount of total pins of all \ac{JTAG} devices
	\end{itemize}
	\item Finally the determined value will be updated and visible as textual representation at the bottom of the tool
\end{enumerate}

\begin{lstlisting}[language={[Sharp]C},caption={GenerateNewVector of SVFHelper},captionpos=b,label=lst:GenerateNewVector]
private string GenerateNewVector(string pinLabel, bool value, Dictionary<int, IBoundaryCell> boundaryCells, ref int position, byte[] defaultVector)
{
		var index = 0;
		foreach (var cell in boundaryCells)
		{
				if (cell.Value.Port.Equals(pinLabel))
				{
						index = cell.Key;
						position = index;
						break;
				}
		}

		if (index == 0)
		{
				return string.Empty;
		}

		var vectorArray = new BitArray(defaultVector);
		try
		{
				vectorArray.Set(index, value);
		}
		catch (ArgumentOutOfRangeException e)
		{
				logger.LogMessage(e.Message, LogCategory.ERROR);
		}

		byte[] resultBytes = new byte[((vectorArray.Length - 1) / 8) + 1];
		vectorArray.CopyTo(resultBytes, 0);
		Array.Reverse(resultBytes, 0, resultBytes.Length);
		return ByteArrayToString(resultBytes);
}
\end{lstlisting}

As shown in \ref{lst:GenerateNewVector} there will be first searched after the pin label within the dictionary recevied by the \ac{BSDL} file. If a valid index was found then the default vector will be converted into a bit array and the specific index of the pin will be set to the requested value. Finally the bit array will be converted back to a hexadecimal representation. If there was no index found at all just an empty string will be returned to trigger the logging of missing pin information within the \ac{BSDL} file. The default vector must be read out directly before creation of \ac{SVF} files and contains all actual states of pins in a hexadecimal representation.
